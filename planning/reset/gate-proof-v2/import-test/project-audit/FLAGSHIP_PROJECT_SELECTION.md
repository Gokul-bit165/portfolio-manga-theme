# Flagship project selection

**This is a proposal for the owner.** It follows the brief's six candidates, with one change, which the evidence forces: MuleNet becomes HAC-FEW. The order is the brief's.

| # | Standard | Project | Why it is in the lineup | Status shown to visitors |
|---|---|---|---|---|
| I | Loom AI | Loom AI, Textile Manufacturing Intelligence | Grounded AI: the LLM explains, and deterministic code computes every number, with source traceability; there is a documented test suite | Working product, team |
| II | TerraTrace | TerraTrace ORBIT | Geospatial AI workflow design for a defence problem statement (SIH26227) | **Interface prototype; data simulated** |
| III | NENAI | NENAI, offline AI memory | On-device LLM and vector search, with privacy by construction | Working product, team. **The owner's role needs confirming.** |

| VI | HAC-FEW | HAC-FEW, hierarchical agent coordination | Agentic AI with governance: supervisor planning, approvals and an audit trail | Team project, in a teammate's repository |

## Why MuleNet is out

Its repository holds no model, training or evaluation code, and the owner made no commits to it. The dataset is generated at random. The resume's metrics cannot be traced to any artefact.

If MuleNet's model and evaluation exist somewhere else (a notebook, a private repository, a report), sending them would let MuleNet return, as a research prototype on **synthetic data**. Graph ML would fill the lineup's one remaining gap.

## Why HAC-FEW replaces it

The owner's commits are 97% of the lines in the upstream repository: the platform API, the React console and the core automation. It covers what the brief's goal names: agentic systems, governance, graph-structured knowledge (GraphRAG) and full stack. The alternative is NPC-TraceGuard (95% the owner's), which brings explainable risk scoring.
